# typebud sound pack format

This is the contract between the pack files in `sounds/packs/` and the app's
loader. Version: **format `typebud.soundpack`, format_version 1**.

The packs in this repo are generated by `scripts/sounds/import_pack.py` and
checked by `scripts/sounds/preview.py`. A pack that passes `preview.py`
conforms to this document.

Sections 1–6 describe typebud's own format, which is what the app bundles and
should load at runtime. Section 7 describes the Mechvibes / MechvibesDX pack
formats, which the app also accepts as user imports.

---

## 1. Layout

```
sounds/packs/
  index.json                 list of bundled packs, in display order
  <id>/
    pack.json                metadata + sample lists (section 3)
    LICENSE                  license and attribution for the audio in this folder
    down/<pool>_<NN>.wav     key-down samples
    up/<pool>_<NN>.wav       key-up samples (optional)
```

* `<id>` is the folder name and must equal `pack.json` `id`.
* The file names above are what the importer writes. The loader must **not**
  infer anything from file names. It uses only the lists in `pack.json`.

### index.json

```json
{
  "format": "typebud.soundpack-index",
  "format_version": 1,
  "packs": [
    { "id": "nk-cream", "bundle": "default" },
    { "id": "model-m",  "bundle": "optional-gpl" }
  ]
}
```

| field | type | meaning |
|---|---|---|
| `packs[].id` | string | a folder under `sounds/packs/` |
| `packs[].bundle` | `"default"` \| `"optional-gpl"` | `default`: may ship inside the MIT-licensed app. `optional-gpl`: GPL-licensed audio, distributed only as a separate data pack with its own LICENSE. See `LICENSES.md`. |

The array order is the order the packs appear in the UI. Unknown `bundle`
values are treated like `optional-gpl`: don't bundle.

## 2. Audio files

Every sample file referenced by `pack.json` is:

* RIFF/WAVE, `WAVE_FORMAT_PCM` (format tag 1), **16-bit signed little-endian,
  1 channel, 48 000 Hz**. No `WAVE_FORMAT_EXTENSIBLE`, no other rates.
  Any other chunks (`LIST` etc.) may appear and must be skipped. Today's files
  hold only `fmt ` and `data`.
* Short: key-down ≤ 260 ms, key-up ≤ 200 ms (bundled packs: 47–220 ms).
* **Onset-aligned:** the strike starts 1.0 ms after the first sample. More
  precisely, the 0.25 ms RMS envelope first reaches −20 dB relative to its
  peak at 1.0 ms (measured over all bundled samples: 0.94–2.12 ms, median
  1.00 ms). The 1 ms before it is a fade-in from digital silence. Play a sample
  the moment the key event arrives, with no offset compensation.
* **Tail faded:** the last ~12 ms is a cos² fade to zero. Samples end at 0, so
  they can be cut or mixed without clicks.
* **Peak ≤ −1 dBFS** per sample.
* **Loudness-matched across packs:** the median key-down `generic` sample of
  every pack has the same "strike loudness" (−23 LUFS, K-weighted, over a fixed
  50 ms window from sample start). Switching packs does not change perceived
  volume, so the app needs no per-pack gain. Within a pack, variants of one
  pool are within ±2 dB of each other. Special keys (space/enter/…) are at
  most 4 dB louder than letters. Key-ups are never louder than key-downs.

The app's mixer must still leave headroom or use a limiter. Overlapping sounds
(the next key-down during the previous key's tail, shift + letter, key-up +
next key-down) add up. In `preview.py`'s typing renders the summed peak
reaches **+2.0 dBFS** for `topre` and about 0 dBFS for `nk-cream`, `box-navy`
and `low-profile-brown`. A master gain of −3 dB, or a soft limiter on the mix
bus, is enough.

## 3. pack.json

Example (abridged from `nk-cream`):

```json
{
  "format": "typebud.soundpack",
  "format_version": 1,
  "id": "nk-cream",
  "name": "NovelKeys Cream",
  "description": "Smooth, creamy self-lubricating linear switch with a soft, muted bottom-out.",
  "author": "Thomas Lai (kbsim)",
  "license": "MIT",
  "license_file": "LICENSE",
  "attribution": "Sound samples from kbsim by Thomas Lai (https://github.com/tplai/kbsim), MIT License. ...",
  "source": { "url": "https://github.com/tplai/kbsim", "commit": "ba103f3b...", "path": "src/assets/audio/cream" },
  "switch_type": "linear",
  "tags": ["linear", "creamy", "quiet"],
  "audio": { "sample_rate": 48000, "channels": 1, "encoding": "pcm_s16le", "container": "wav" },
  "loudness": { "reference": "...", "target_lufs": -23.0, "gain_applied_db": 13.3, "peak_ceiling_dbfs": -1.0 },
  "playback": { "pitch_jitter_cents": 15, "gain_jitter_db": 1.0 },
  "sounds": {
    "down": {
      "generic":   ["down/generic_01.wav", "down/generic_02.wav", "down/generic_03.wav", "down/generic_04.wav", "down/generic_05.wav"],
      "space":     ["down/space_01.wav"],
      "enter":     ["down/enter_01.wav"],
      "backspace": ["down/backspace_01.wav"]
    },
    "up": {
      "generic":   ["up/generic_01.wav"],
      "space":     ["up/space_01.wav"],
      "enter":     ["up/enter_01.wav"],
      "backspace": ["up/backspace_01.wav"]
    }
  }
}
```

### Fields

UTF-8 JSON object. **R** = required: reject the pack if it is missing or has
the wrong type. Every other field is optional, and the loader uses the default
shown when it is absent. Unknown fields must be ignored, so later versions can
add fields without breaking older loaders.

| field | R | type | default | meaning |
|---|---|---|---|---|
| `format` | R | string | | must be `"typebud.soundpack"` |
| `format_version` | R | integer | | must be `1`. Reject higher versions. |
| `id` | R | string | | `^[a-z0-9][a-z0-9-]{0,63}$`, equal to the folder name |
| `name` | R | string | | display name |
| `author` | R | string | | display credit |
| `license` | R | string | | SPDX identifier (`MIT`, `CC0-1.0`, `GPL-2.0-only`, …) or `NOASSERTION` |
| `sounds` | R | object | | section 4 |
| `description` | | string | `""` | one-line description for the UI |
| `license_file` | | string | none | relative path of the license text, normally `LICENSE` |
| `attribution` | | string | `""` | text to show in the app's credits screen. Show it verbatim. |
| `source` | | object | `{}` | provenance, informational. One of `{url, commit, path}` (imported from a repo), `{generator}` (synthesized), `{imported_from}` (user import). |
| `switch_type` | | string | `"unknown"` | `linear`, `tactile`, `clicky`, `buckling-spring`, `topre`, `low-profile`, `synthetic`, `unknown`. Unknown values display as `unknown`. |
| `tags` | | string[] | `[]` | free-form, for filtering |
| `audio` | | object | | informational. Restates section 2. The loader checks the WAV headers themselves, not this field. |
| `loudness` | | object | | informational. Records what the importer did. |
| `playback.pitch_jitter_cents` | | number ≥ 0 | `0` | random pitch offset per hit, uniform in ±value cents. 0 = off. |
| `playback.gain_jitter_db` | | number ≥ 0 | `0` | random gain offset per hit, uniform in ±value dB. 0 = off. |

Paths in `sounds` and `license_file` are relative to the pack folder and use
`/`. A path must not be absolute, contain `..`, or contain `\`. Reject the pack
if one does: user packs are untrusted input.

## 4. `sounds` and key classes

```
"sounds": {
  "down": { <pool>: [<path>, ...], ... },    required
  "up":   { <pool>: [<path>, ...], ... }     optional (omit when the pack has no key-up sounds)
}
```

`<pool>` is `generic` or one of the app's `GlobalKeyClass` names:

| pool | keys |
|---|---|
| `generic` | fallback for every class. Required, and non-empty, in `down`. |
| `letter` | A–Z (and other alphabetic keys of the layout) |
| `digit` | number-row 0–9, numpad digits |
| `space` | space bar |
| `enter` | Return, numpad Enter |
| `backspace` | Backspace (and forward Delete, if the app chooses) |
| `tab` | Tab |
| `modifier` | Shift, Ctrl, Alt/Option, Meta/Cmd/Win, Caps Lock, Fn, Menu |
| `arrow` | the four arrow keys |
| `other` | everything else: punctuation, F-keys, Esc, navigation cluster, numpad operators |

Rules:

* Pool names other than the ten above: ignore that pool and log it. Don't
  reject the pack, so a future version can add classes.
* Lists hold 1–32 paths, each naming a file that exists and passes section 2.
  If any listed file is missing or malformed, reject the pack. Don't load half a
  pack.
* The same path may appear in more than one pool.
* An empty list is the same as an absent pool.

### Choosing a sample (normative)

For a key event with class `C` and direction `D` (`down` or `up`):

1. `pool = sounds[D][C]` if it exists and is non-empty, else
   `sounds[D]["generic"]` if it exists and is non-empty, else **play nothing**.
   So a pack without `up` is silent on key release. There is no fallback from
   `up` to `down` and no cross-class fallback (e.g. `digit → letter`).
2. Pick one entry uniformly at random. If the pool has more than one entry,
   don't pick the entry played last for this `(D, pool)`.
3. Apply `gain_jitter_db` and `pitch_jitter_cents` (independent uniform
   draws). Pitch jitter is a playback-rate change (rate = 2^(cents/1200)),
   which also changes the duration slightly. That is intended.
4. Auto-repeat: the OS repeats key-down events while a key is held. Play a
   key-down sound only on the first down after an up for the same key. Play
   key-up on release.
5. Polyphony: sounds overlap. Never cut a playing sample to start a new one,
   except when a voice limit is reached; then steal the oldest voice. 16 voices
   are enough.

`scripts/sounds/preview.py` (`resolve()` and `render()`) is a reference
implementation of steps 1–3.

### What the bundled packs contain

| id | down pools (variants) | up pools (variants) |
|---|---|---|
| nk-cream, holy-panda, mx-brown, box-navy, alps-blue, buckling-spring, topre | generic 5, space 1, enter 1, backspace 1 | generic 1, space 1, enter 1, backspace 1 |
| low-profile-brown | generic 5, space 3, enter 2, backspace 2 | same |
| bubble-pop | generic 8, space 2, enter 1, backspace 1, modifier 2 | generic 4, space 1 |
| model-m (optional-gpl) | generic 12, digit 3, space 1, enter 1, backspace 1, tab 1, modifier 4, arrow 2 | same |

The kbsim-derived packs have no distinct modifier/tab/arrow recordings. Those
keys use `generic` through rule 1.

## 5. Validation summary for the loader

Reject the pack (and log the reason) if:

* `pack.json` is missing, not valid JSON, or `format`/`format_version` mismatch;
* `id` does not match the folder, or a required field is missing/mistyped;
* `sounds.down.generic` is missing or empty;
* any path is absolute, contains `..` or `\`, or names a missing file;
* any listed WAV is not PCM 16-bit mono 48 kHz, or has an empty `data` chunk.

Accept, ignoring the offending part, when there are unknown fields, unknown
pool names, or unknown `switch_type` values.

---

## 6. Licensing obligations

* `license` + `license_file` + `attribution` must be kept with the pack and
  shown in the app's credits/about screen for every pack the app ships or has
  installed.
* Packs with `bundle: "optional-gpl"` in `index.json`, or `license` starting
  with `GPL`, must not be compiled into or shipped inside the MIT-licensed app
  binary/installer. Distribute them as a separate download/folder with their
  LICENSE file. See `LICENSES.md`.

## 7. Mechvibes / MechvibesDX packs (user import)

The app also accepts packs made for Mechvibes and MechvibesDX, and Thock's
pack layout. Recommended implementation: convert on import to the format
above, then load the result like any other pack. `import_pack.py import <pack
folder> <out>` does exactly this conversion and is the reference for the
mapping. A Zig importer should give the same result, minus the loudness
processing, which is optional for user packs.

Converting a foreign pack needs decoders for **OGG Vorbis, MP3 and WAV**
(FLAC rarely appears), downmix to mono, and resampling to 48 kHz. Every path
inside a foreign `config.json` is untrusted: resolve it against the pack
folder and reject it if it escapes that folder. Match file names
case-insensitively as a fallback, since packs made on Windows/macOS are often
inconsistent.

The format is detected from `<pack>/config.json`:

| detection | format |
|---|---|
| has `metadata` and `sounds` | Thock |
| has `definitions` or `defs` | MechvibesDX (config_version 2) |
| has `defines` | Mechvibes v1 / v2 (`version` field, default 1) |
| no config.json, has `press/` folder | kbsim layout (`press/`, `release/`, `GENERIC_R<n>`, `SPACE`, `ENTER`, `BACKSPACE`) |

### 7.1 Mechvibes v1, `key_define_type: "single"` (sprite)

```json
{ "id": "...", "name": "EG Oreo", "key_define_type": "single", "includes_numpad": false,
  "sound": "oreo.ogg",
  "defines": { "1": [971, 142], "2": [1276, 115], "30": [5500, 120], "57": [9100, 180], "2": null } }
```

* `sound`: one audio file holding every key.
* `defines`: key code → `[start_ms, duration_ms]` within `sound`, or `null` (no
  sound). The slice is `[start, start + duration)`.
* No key-up sounds.

### 7.2 Mechvibes v1, `key_define_type: "multi"` (one file per key)

```json
{ "name": "NK Cream", "key_define_type": "multi", "sound": "sound.ogg",
  "defines": { "16": "q.wav", "57": "space.wav", "28": "enter.wav" } }
```

* `defines`: key code → file name (whole file is the sample), or `null`.
* `sound` is unused in v1 multi.
* No key-up sounds.

### 7.3 Mechvibes v2 (`"version": 2`, multi)

```json
{ "name": "MX Brown - Full Travel", "key_define_type": "multi", "version": 2,
  "sound":   "press/GENERIC_R{0-4}.mp3",
  "soundup": "release/GENERIC.mp3",
  "defines": { "14": "press/BACKSPACE.mp3", "14-up": "release/BACKSPACE.mp3",
               "57": "press/SPACE.mp3",     "57-up": "release/SPACE.mp3" } }
```

* Keys `"<code>-up"` are key-up sounds for `<code>`.
* `sound` / `soundup` are the default key-down / key-up for any key not in
  `defines`, and become the `generic` pools.
* `{a-b}` in any file name expands to the integers `a..b` inclusive, one
  variant per value (`GENERIC_R{0-4}.mp3` → 5 files).
* v2 with `key_define_type: "single"`: as 7.1, plus `"<code>-up": [start_ms,
  duration_ms]` entries.

### 7.4 Mechvibes key codes → GlobalKeyClass

Mechvibes uses libuiohook virtual key codes. The low ones equal PC scan code
set 1, which is also how bucklespring names its files. Anything not listed is
`other`.

| class | codes (decimal) |
|---|---|
| letter | 16–25 (Q…P), 30–38 (A…L), 44–50 (Z…M) |
| digit | 2–11 (1…0) |
| space | 57 |
| enter | 28, 3612 (numpad Enter) |
| backspace | 14 |
| tab | 15 |
| modifier | 42, 54 (Shift L/R), 29, 3613 (Ctrl L/R), 56, 3640 (Alt L/R), 3675, 3676 (Meta L/R), 3677 (Menu), 58 (Caps Lock) |
| arrow | 57416, 57419, 57421, 57424, 61000, 61003, 61005, 61008 (Up, Left, Right, Down; two encodings seen in packs) |

On conversion, `letter`, `digit` and `other` samples all go into the
`generic` pool. A Mechvibes pack has one sample per key, so per-class pools
would hold one or two variants and sound repetitive; the generic pool gets
every letter key's sample as a variant. `space`, `enter`, `backspace`, `tab`,
`modifier` and `arrow` keep their own pools. The importer caps pools at 8
generic and 3 per special class, picked evenly across the key list. If a pack
defines no generic sound, the largest pool is used as `generic`.

### 7.5 MechvibesDX (`config_version: "2"`)

```json
{ "config_version": "2", "name": "EG Oreo", "author": "Mechvibes",
  "definition_method": "single", "audio_file": "oreo.ogg",
  "definitions": {
    "KeyA":  { "timing": [[21399.0, 21458.5], [21458.5, 21518.0]] },
    "Space": { "timing": [[9100.0, 9280.0]] } } }
```

* Keys are W3C `KeyboardEvent.code` names: `KeyA`…`KeyZ` → letter,
  `Digit0`…`Digit9` → digit, `Space`, `Enter`/`NumpadEnter`, `Backspace`,
  `Tab`, `Shift*/Control*/Alt*/Meta*/OS*`, `CapsLock`, `ContextMenu`, `Fn` →
  modifier, `Arrow*` → arrow, everything else → other. Keys starting with
  `Mouse`, `Wheel` or `Button` are mouse sounds and are skipped.
* `timing` holds `[start_ms, end_ms]` pairs with **absolute end** times,
  unlike Mechvibes v1's durations. MechvibesDX itself plays `timing[0]` on key
  down and `timing[1]` (if present) on key up. Its own docs describe the pairs
  as random variants, but the engine code (`lookup_timing` in
  `src/libs/audio/engine.rs`) does down/up.
* Migration artifact: packs converted from Mechvibes v1 by MechvibesDX have
  both pairs back-to-back (`timing[1][0] == timing[0][1]`). That is one
  key-down cut in half, not a real key-up. When the two pairs are contiguous,
  join them into a single key-down `[timing[0][0], timing[1][1]]` and import
  no key-up for that key. All bundled MechvibesDX keyboard packs are like
  this.
* `definition_method: "multi"` packs (one file per key) are converted by
  MechvibesDX itself to `single` on first load and are rare in the wild. They
  are not supported; reject with a clear message.

### 7.6 Thock

```json
{ "metadata": { "name": "...", "author": "...", "supportsKeyUp": true },
  "license":  { "type": "MIT", "url": "..." },
  "sounds": { "default": { "down": ["1.wav", "2.wav"], "up": ["101.wav"] },
              "space":   { "down": ["3.wav"], "up": ["201.wav"] } } }
```

Each `sounds` key is a pool. `default` maps to `generic`. Other keys map to
the pool of the same name when it is one of the pools in section 4, else to
`generic`. `license.type` is carried over into `license`.

### 7.7 Licensing of imported packs

Foreign packs rarely state an audio license. Set `license` from the pack's own
metadata, or to `NOASSERTION`. Never bundle an imported pack. Imported packs
stay in the user's data directory.
